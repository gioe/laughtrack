# Show intake and suppression

Rejection defaults to one occurrence. Durable keys retain namespaced native performance IDs scoped to venue, source/event ownership, provider event IDs, recognized Ticketmaster/Eventbrite event URL IDs, and legacy physical slots only when no native performance ID exists. Public row IDs are retained as aliases. A title is never a key. Missing or conflicting identity holds intake; a policy outage cannot fall back to publication.

Ticketmaster and Eventbrite adapters carry raw event IDs separately from physical storage conflict keys. Eventbrite's explicit series_id is retained separately, namespaced and scoped to the owning scraping source. Other adapters may populate Show.curation_series_id only from an actual provider series ID, never a title, organizer or calendar URL. Providers without stable IDs cannot be recognized after every identity signal changes; ambiguous occurrences require review rather than a global title ban.

curation_show_mappings records confirmed equivalence from eligibility publication links, including links already present at migration time. curation_show_series_members associates occurrences with explicit source-owned series identities. Both retain evidence/ownership and cannot be silently rewritten. curation_register_show_series(source_id, native_id, label) registers an identified series for review, not a block. The shared admin show adapter previews exact keys, public events and additional staged identities. Series blocks are explicit separate decisions; unsupported or ambiguous series targets are refused.

The scraper preflight records observations before comedy classification, including off/shadow paths. Database triggers independently enforce every INSERT/UPDATE and guard publication races. Applied Event Review rejection writes an occurrence block in the worker transaction; submitted/stale requests do not. Existing source, generation, fingerprint and version fences remain. A new classifier decision cannot override the durable rejection. Generic curation uses the same immediate adapter/ledger contract as the other domains.

Blocks set shows.visible=false and retain saved-show, ticket, lineup and audit references. Public searches, counts, detail, ticket redirects, notification feeds and discovery rails filter suppressed rows. A database publication revision invalidates public home/search/detail/stat caches after visibility or cancellation changes, including worker decisions; unavailable revision state fails closed. Notification delivery rechecks visibility after fetching candidates, before email/grouped push. Delivery already in flight cannot be recalled. Stale-show cleanup excludes suppressed rows; database deletion guards preserve them too.

Restore returns an occurrence to pending review, never republishes it. Subsequent approval also leaves visibility untouched. A series restore removes that series block without republishing historical shows. Other occurrence/series, venue, cancellation and eligibility holds remain independent. Publication requires those checks and a deliberate visibility change for existing rows.

The shared intake lock is acquired before source/entity locks. It serializes policy/publication for correctness; monitor lock contention at rollout.
